# iConnect on Render — Option A, step by step

This guide deploys the **API + web app** to Render free tier and gets you a public
URL ending in `/api`. This is the min steps, using the included `render.yaml`
blueprint.

> If you use the manual Web Service path instead of the blueprint, the settings are
> in **"Option B: Manual Web Service (fallback)"** at the bottom.

---

## What you need before you start

- A GitHub account with this repo (already connected: `HiamIsrael/iConnect`).
- A Render account (free): https://render.com — sign up with GitHub.

---

## Option A: Render Blueprint (recommended, ~2 minutes)

This repo includes `render.yaml`, so Render can create the whole service for you.

1. Log in to https://render.com.

2. Click **New** (top right) → **Blueprint**.

3. Click **Connect account** and authorize Render to read your GitHub repos
   (use the same GitHub account that owns `HiamIsrael/iConnect`).

4. Pick the **iConnect** repository.

5. On the "Blueprint" page confirm the detected service:
   - Name: `iconnect-api`
   - Runtime: **Node**
   - Plan: **Free**
   - Build command: `npm install && npm run build`
   - Start command: `npm start`

6. Click **Apply**. Render will:
   - Create the web service,
   - Run `npm install` (this installs Express, better-sqlite3, etc.),
   - Run `npm run build` (compiles the web UI in `dist/`),
   - Start `node server/index.js` (runs migrations + seeds demo data automatically).

7. Wait ~2–5 minutes. When it's live, Render shows a public URL like:
   ```
   https://iconnect-api.onrender.com
   ```

**That URL is your public API root.** It also serves the full web app, because
`npm start` serves `dist/` (the built React UI) plus the API.

## Verify the URL (do this before going further)

Click "Open" on Render or paste this in your browser/terminal:

```bash
curl https://iconnect-api.onrender.com/api/health
```

The **required** result is:

```json
{"ok":true,"name":"iConnect","version":"0.3.0","storage":"sqlite"}
```

Then confirm the built web UI loads:

```bash
curl -I https://iconnect-api.onrender.com
```

And log in via the web app itself (full UI, no mobile build needed):
- Email `ayo@example.com`
- Password `password123`

## Important Render settings after the first deploy

1. **Set `APP_URL`** so emails/payment links use the real URL.

   Render Dashboard → **Environment** → edit `APP_URL`:

   ```
   https://iconnect-api.onrender.com
   ```

   (No `/api`, no trailing slash.) Save, then **Manual Deploy → Deploy latest
   commit** (or "Restart service").

2. `JWT_SECRET` is auto-generated by the blueprint. If you used the manual
   path, set a long random value: `openssl rand -hex 32`.

3. **Free tier sleeps after ~15 minutes idle.** The first request after a nap can
   take 30–60 seconds to wake. That's normal. For always-on, upgrade to the
   paid hourly plan or use a paid instance.

4. **SQLite data is on the container's disk and is not persistent across
   redeploys on the free tier.** That's fine for a demo (the DB reseeds on boot,
   so demo accounts always exist). If you want real persistence, create a
   **Postgres** database in Render, set `DATABASE_URL`, and redeploy — the app
   supports Postgres via Knex.

## Option B: Manual Web Service (fallback)

If the blueprint path doesn't auto-detect, use this instead.

1. Render → **New** → **Web Service**.
2. Connect GitHub → choose **iConnect**.
3. Settings:
   - **Name:** `iconnect-api`
   - **Region:** closest to you
   - **Branch:** `main` (after merging this session branch into `main`)
   - **Runtime:** Node
   - **Build command:** `npm install && npm run build`
   - **Start command:** `npm start`
   - **Instance type:** Free
4. **Advanced → Environment variables (add these before creating):**
   - `NODE_ENV` = `production`
   - `JWT_SECRET` = a long random string (`openssl rand -hex 32`)
   - `EMAIL_PROVIDER` = `console`
   - `PAYMENT_PROVIDER` = `mock`
   - `APP_URL` = leave blank now; set it after you have the URL
5. Click **Create Web Service**.
6. Wait for it to deploy, then do the "Verify the URL" step above.

## Common issues

- **`/api/health` times out on first hit** → the free instance was asleep; wait
  30–60s and retry (or upgrade to always-on).
- **Build fails on `better-sqlite3`** → Render's Node runtime usually has the
  build tools (`python3`, `make`, `g++`). If it ever fails, set
  `NPM_CONFIG_PYTHON` and/or use the **Docker** runtime (this repo has a
  `Dockerfile`), or switch to **Postgres** so the native SQLite addon is not used.
- **Demo login fails after restart** → if you set `DATABASE_URL` to Postgres
  after the first seed, wipe the database and let it reseed, or verify the
  seed ran in the Render logs ("Demo login: ayo@example.com...").
